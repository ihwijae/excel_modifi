# 기능 분석 및 수정 내역 (2025-10-16)

이 문서는 프로그램의 주요 기능 로직과 최근에 진행된 버그 수정 및 개선 사항을 요약합니다.

---

## 1. 신규 업체 데이터 추가 로직

### 1-1. 핵심 동작 방식

신규 업체 데이터는 다음 두 가지 시나리오에 따라 추가됩니다.

- **Case 1: 기존 구간에 빈 슬롯이 있을 경우**
  - 프로그램은 '회사명' 행을 기준으로 B열부터 M열까지 순차적으로 탐색하여 빈 열을 찾습니다.
  - 빈 열을 발견하면, 해당 열에 신규 업체 정보를 삽입합니다.
  - 이 경우, 이미 서식이 존재하는 빈칸을 채우는 것이므로 별도의 서식 생성 작업은 수행하지 않습니다.

- **Case 2: 모든 구간이 가득 찼을 경우**
  - 시트의 모든 구간(B~M열)이 데이터로 채워져 있으면, 시트 맨 아래에 새로운 구간을 생성합니다.
  - **(수정됨)** 이때, 바로 직전 구간의 서식을 복사하여 새 구간을 만듭니다.
    - **A열 (라벨):** 값과 모든 서식(글꼴, 테두리, 채우기 색 등)을 그대로 복사합니다.
    - **B~M열 (데이터):** 값은 비워두고, 채우기 색을 **제외한** 모든 서식(글꼴, 테두리, 정렬 등)만 복사합니다. 이를 통해 데이터 상태를 나타내는 색상이 새 구간에 잘못 적용되는 것을 방지합니다.

### 1-2. 관련 버그 수정

- **문제 현상:** 중간에 빈 행이 있는 구간에 데이터를 추가할 때, 다음 업체의 '회사명' 위치에 데이터를 덮어쓰는 버그.
- **원인:** 데이터를 삽입할 행 번호를 찾는 과정에서, 현재 구간의 범위를 벗어나 다음 구간의 라벨까지 잘못 읽어오는 로직 오류 (`ocr_logic.py`).
- **조치:** 라벨을 스캔하는 반복문의 범위를 정확히 현재 구간 내로 한정하여 수정 완료했습니다.

## 2. 데이터 위치 탐색 원리 (`config.py` 활용)

프로그램은 '수정'과 '신규 등록' 시에 각각 다른 방식으로 데이터의 정확한 위치를 찾습니다.

- **기존 업체 수정 시:**
  1.  엑셀 시트에서 고유한 **'사업자등록번호'** 의 위치를 찾습니다.
  2.  `config.py`의 `RELATIVE_OFFSETS` 딕셔너리에 정의된 **고정된 상대 위치**를 이용해 '대표자'(-1), '부채비율'(+5) 등 다른 정보들의 셀 위치를 빠르게 계산하여 업데이트합니다.

- **신규 업체 등록 시:**
  1.  `config.py`의 `COLUMN_MAP`을 통해 프로그램 내부 데이터 키(예: '상호')와 엑셀 라벨('회사명')을 연결합니다.
  2.  데이터를 추가할 구간이 정해지면, 해당 구간의 **A열을 직접 스캔하여** '회사명', '대표자' 등 각 라벨의 **실제 행 번호를 실시간으로 파악**합니다.
  3.  이 정보를 바탕으로, 이름이 정확히 일치하는 행에 데이터를 안전하게 삽입합니다. 이 방식은 템플릿 구조가 변경되어도 유연하게 대처할 수 있습니다.

## 3. '자료 파일 없이 데이터 저장' 기능 개선

- **문제 현상:** 해당 기능을 체크하고 신규 업체를 추가하려고 하면 "사업자번호를 찾을 수 없다"는 오류가 발생하며 진행되지 않았습니다.
- **원인:** 해당 기능이 기존 업체 '수정'만을 가정하고 만들어져, 신규 업체 추가 로직을 호출하는 부분이 없었습니다.
- **조치:** '자료 파일 없이 저장' 모드에서도 프로그램이 신규 업체인지 기존 업체인지 먼저 판단하여, 신규 업체일 경우 `add_new_company_data` 함수를 호출하도록 `business_status_tab.py`의 로직을 수정했습니다.

## 4. 폰트 로딩 문제 해결

- **문제 현상:** 프로그램 실행 시 `Failed to create DirectWrite face` 및 `폰트 파일을 불러오는 데 실패했습니다` 라는 경고 로그가 표시되었습니다.
- **원인:** UI 프레임워크(Qt)가 웹 전용 폰트 형식인 `.woff2`를 제대로 지원하지 않아 발생했습니다.
- **조치:**
  1.  `fonts` 폴더의 모든 `.woff2` 파일을 삭제하고, 데스크톱 환경에서 표준적으로 사용되는 `.ttf` 형식의 `Pretendard-M.ttf` 파일로 교체했습니다.
  2.  `main.py`의 폰트 로딩 코드를 수정하여, 새로 추가된 `.ttf` 파일을 불러오도록 변경했습니다.
